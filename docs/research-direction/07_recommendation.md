# 07 — 最终建议 (Final Recommendation)

> 状态：已修订（v3）| 更新日期：2026-07-30
> 关键修正：分阶段实验（先合成预实验→单数据集48次→按信号扩展）、区分"选择策略等价性"和"探索vs复验预算分配"、承认AutoPEFT已有可靠性报告和EHPO已有一般性结论

---

## 修订原因

初始调研后，我建议将"预算感知 PEFT Agent"作为第一篇论文。进一步审查发现相邻工作比预期密集得多：

| 相邻工作 | 做了什么 | 与初始方案的冲突 |
|---|---|---|
| **AutoPEFT** ([TACL](https://doi.org/10.1162/tacl_a_00662)) | 贝叶斯优化自动选择 PEFT 配置 | 直接冲突——"自动选择 PEFT"已有 |
| **BIPEFT** ([EMNLP 2024 Findings](https://arxiv.org/abs/2410.09079)) | 预算引导的迭代 PEFT 搜索 | 直接冲突——"预算感知 PEFT 搜索"已有 |
| **MetaPEFT** ([CVPR 2025](https://openaccess.thecvf.com/content/CVPR2025/html/Tian_Meta-Learning_Hyperparameters_for_Parameter_Efficient_Fine-Tuning_CVPR_2025_paper.html)) | 元学习 PEFT 超参数 | 直接冲突——"学习如何选择 PEFT HP"已有 |
| **数据清洗 AutoML** ([2022](https://link.springer.com/article/10.1007/s13222-022-00413-2)) | 将数据清洗作为 AutoML 搜索变量 | 直接冲突——"数据质量×AutoML联合"已有 |
| **DataMaster** ([arXiv 2026](https://arxiv.org/abs/2605.10906)) | Agent 自动数据发现→清洗→转换 | 直接冲突——"Agent 管数据"已有 |

**结论**："Agent 自动选择 PEFT + CleanLab + 超参数"是已有模块的拼装，不够新。

---

## 重新定义的研究主线

> **面向小数据微调的可信自动实验：在有限算力、微小且不可靠的验证数据下，如何稳定地选择真正能泛化的 PEFT 配置？**

这个框架的科学问题是**"搜索得到的最优配置是否真的最优"**，而不是"能不能自动搜索"。后者已被 AutoPEFT/BIPEFT 解决；前者是所有现有系统都没回答的问题。

### 与相邻工作的差异

| 维度 | AutoPEFT/BIPEFT/MetaPEFT | 本工作 |
|---|---|---|
| **目标** | 自动找到最优 PEFT 配置 | **找到的配置是否可靠** |
| **评估** | 报告验证准确率最高值 | 报告选择后悔值（test gap）、排名稳定性、方差 |
| **输出** | 一个"最优"配置 | **配置 + 置信区间 + 失败风险** |
| **对搜索的态度** | 越多越好 | **搜索过多可能加剧验证集过拟合** |

## 推荐主线 🥇：ReliablePEFT

### 暂定题目

> **ReliablePEFT：小数据视觉 PEFT 自动选择的稳定性与选择偏差基准**

### 三个核心科学问题

1. **排名稳定性**：不同随机种子、数据划分和验证集规模下，PEFT 方法排名是否稳定？排名逆转的频率和幅度有多大？
2. **搜索-过拟合 trade-off**：搜索配置越多，验证集最优值与真实测试性能之间的差距（选择后悔值）是否越大？
3. **可靠选择方法**：使用风险规避策略（而非最大化验证准确率），能否降低选择后悔值？

### 第一阶段实验（推荐首发）：48 次训练 + 离线模拟

#### 实验设计

**固定因素**（最大化控制变量）：
- 数据集：**EuroSAT**（10 类，卫星遥感，与自然图像差异大）——先只用这一个
- 骨干：固定一个 ViT-B/16（预训练权重冻结）
- 方法：**只用 LoRA**（暂时不涉及跨方法比较）
- 配置池：16 个 LoRA 配置，覆盖 rank、learning rate、weight decay、target modules
- 每个配置：3 个训练种子，固定 epoch（不使用验证集早停）
- 训练标签保持干净（避免"没训练好"与"配置选错"混淆）

**总计**：`16 × 3 = 48` 次训练（单 RTX 5080 约 4-6 小时）

#### 保存的数据

每次训练保存验证集和测试集的**逐样本 logits**，支持完全离线模拟：
- 候选配置数：4、8、12、16
- 验证样本数：每类 1、2、4 个
- 多个验证集重采样
- 0%、10%、20% 验证标签噪声注入

#### 四种真正值得比较的选择策略

这些策略从根本上不同——不依赖 LCB/Bootstrap/Pareto 可能等价的风险：

| # | 策略 | 核心机制 | 与 Naive Max 的差异 |
|---|---|---|---|
| ① | **Naive Max** | 全部验证预算用于选择，选准确率最高配置 | 基线（AutoPEFT/BIPEFT 的做法） |
| ② | **选择集＋确认集** | 验证预算划分为二：选择集筛 Top-K；独立确认集从中定最终配置 | **引入独立验证**——关键问题是划分比例 |
| ③ | **跨折排名一致性** | 验证集分若干折，按平均名次或最差名次选择（不按总准确率） | **放弃"总准确率最高"目标**，转而寻求"在各子集上都表现好" |
| ④ | **探索与复验预算分配** | 相同训练次数下比较：(a) 16 配置各跑 1 次；(b) 8 配置各跑 2 种子；(c) 12 配置各跑 1 次+对 Top-2 复验 | **预算分配的 trade-off**——多试新的还是复验旧的 |

#### 阶段 1 只回答三个问题

1. 候选配置越多，验证集赢家的测试后悔值是否增加？
2. 独立确认集能否减少选择错误？
3. 相同 GPU 预算下，多探索配置和重复验证哪个更划算？

#### 核心指标

- **选择后悔值**（主要）：TestAcc(oracle) − TestAcc(selected)
- **选中真实 Top-ε 配置的概率**：选中的配置是否在 oracle 排名前 20% 内
- **验证排名与测试排名的相关性**（Spearman ρ）
- **最终选中模型的测试性能**

⚠️ 测试集只在选择规则冻结后用于事后评价，不参与策略调整。

#### 阶段 0：零 GPU 统计预实验（先于阶段 1）

在跑任何训练前，用合成逐样本预测验证：
- Naive Max、LCB 和普通 Bootstrap 是否经常给出相同排序？
- 验证集小时，搜索更多配置如何同时影响"真正最好配置"和选择偏差？
- 哪些选择策略确实会产生不同决策？

**目的**：避免浪费 GPU 证明显然结果（如 LCB ≈ Bootstrap ≈ Naive Max）。

#### 与 NeurIPS 2021 EHPO 的关系

NeurIPS 2021 的 EHPO 框架已建立一般性结论——"只有重复搜索确认后 HPO 结论才可信"。我们不宣称这一思想全新。我们的差异点是：
- **领域特化**：小数据视觉 PEFT 场景的系统实证（EHPO 未涉及）
- **预算分配规律**：独立确认集的最优比例、探索 vs 复验的 trade-off（EHPO 理论框架的实证实例化）
- **验证噪声注入**：标签噪声对选择可靠性的影响（EHPO 未涉及）

### 阶段 2：出现信号后再扩展

仅当 EuroSAT 上出现明确选择偏差后，才增加：
- DTD（纹理分类）
- dSprites-Orientation（合成图像，可控分布）

此时累计：`3 数据集 × 16 配置 × 3 种子 = 144` 次训练（含阶段 1 的 48 次）。

### 阶段 3：研究方法排名

仅当阶段 1-2 确认问题存在且可靠选择方法有效后，才扩展到跨 PEFT 方法比较。

每种 PEFT（LoRA/SSF/VPT/Adapter/Convpass/BitFit）获得相同搜索预算（如各 8 个配置），比较：
- 默认配置排名
- 调优后排名
- 不同划分下排名
- 相同搜索预算下的排名

这才回答"哪种 PEFT 更稳定"——避免拿充分调优的 LoRA 与未调优的 VPT 比较。

### 论文定位

**不承诺"三种新风险规避算法"**——如果阶段 0 预实验发现 LCB ≈ Bootstrap ≈ Naive Max，这些方法确实等价，不应包装成贡献。

重新定义为：

> **构建可复现的视觉 PEFT 选择可靠性测试床，量化小验证集下探索规模、独立确认和重复实验之间的权衡。**

如果独立确认 / 跨折排名 / 探索复验策略产生稳定收益，再升级为方法贡献；如果没有，仍然获得有发表价值的诊断结论。

### 发表路径

| 有方法贡献 | 纯诊断 |
|---|---|
| CCF-B 会议（ECAI/ICME）或 T2 期刊 | TMLR / CCF-C 会议（ICBINB @ ICLR） |
| 贡献：可靠选择策略 + 系统基准 | 贡献：首次量化视觉 PEFT 选择偏差 |

## 推荐第二篇 🥈：预算感知的可靠控制器

第一篇证明问题存在且简单方法有效后，再做更复杂的系统：

### 什么时候做

- 第一篇已完成投稿或接近完成
- 第一篇的简单 LCB/Bootstrap/Pareto 方法仍有显著后悔值残留
- GPU 预算约束下的动态决策成为瓶颈

### 什么内容

1. **多保真早停**：在第一篇的可靠选择框架基础上，引入 LC-PFN（NeurIPS 2023）进行学习曲线外推早停
2. **不确定性感知的配置选择**：将第一篇的三种策略扩展到多保真度场景
3. **动态实验预算分配**：在固定 GPU 时间内，决定何时停止差配置、何时给好配置更多训练 epoch
4. **数据质量辅助信号**：CleanLab 噪声水平估计作为配置选择的额外特征
5. **LLM Agent 的真正角色**：此时 Agent 才有明确工作——
   - 解释失败配置（"这个配置为什么差？"）
   - 缩小搜索空间（"基于失败历史，下一轮应避开哪些区域？"）
   - 决定下一次实验（"要不要换个数据集划分重新验证？"）
   - 而不是简单包装 Optuna

### 与第一篇的关系

- 第一篇仅验证"选择是否可靠"——方法非常简单，不需要预算感知
- 第二篇在可靠性的基础上加入预算约束和动态决策
- 两篇可以独立发表

## 推荐副线：SysML v2 应用验证

### 调整后的方案

不创建大规模 SysML 图像数据集。更稳的方式：

1. **用 SysML v2 文本语法生成合法模型**（开源：Eclipse SysML v2 Pilot Implementation）
2. **程序化注入语义错误**：
   - 连接错误（错接/漏接的端口）
   - 约束冲突（两个 requirement 互相矛盾）
   - 需求追踪断裂（requirement→component 的 satisfy 关系缺失）
3. **渲染为不同视图**：BDD/IBD/PAR 等 8 种图示类型
4. **用主线形成的可靠微调方法完成**：
   - 图→结构化模型恢复
   - 语义错误检测
   - 一致性校验

### 为什么这个方案更好

| 原方案（图像数据集） | 新方案（文本生成+错误注入） |
|---|---|
| 1000-2000 张手动标注图像 | 程序化生成，无限量 |
| 标注成本高、质量难控 | 错误已知，自动验证 |
| 图像质量受渲染器影响 | 语法→渲染可控 |
| SysML v2 太新（2023），真实图像来源有限 | 从规范生成，不受数据匮乏限制 |

### 发表路径

- **NeurIPS Datasets & Benchmarks Track**：首个 SysML v2 验证基准
- **IEEE SysML Conference** 或 **INCOSE IS**：系统工程社区
- 与第一篇并行推进——可能比第一篇更早产出可发表成果

## 对八个关键问题的回答（修订版）

### 1. "自动微调 Agent"相比标准 AutoML/HPO 的可证伪新意是什么？

**修订**：我们不宣称 Agent 的新意。第一篇贡献的科学问题是"搜索得到的最优配置是否可靠"，而非"如何搜索最优配置"。可证伪点是：如果 PEFT 排名在跨种子/划分下保持稳定，且选择后悔值不随搜索次数增加——我们承认问题不存在。

### 2. 在不增加总预算的前提下，Agent 应优化什么？

**修订**：第一篇不优化搜索过程，而是优化**选择过程**。在已有搜索结果的条件下，不选验证准确率最高的配置，而选"可能泛化最好"的配置（LCB/Bootstrap/Pareto）。

### 3. 最强非 Agent 基线是什么，为什么预期能超过它？

**修订**：第一篇的基线是 Naive Max（所有现有系统的做法）。如果 LCB/Bootstrap/Pareto 不能一致优于 Naive Max——这是有意义的负面结果，仍然可发表。

### 4. 小数据微调的哪个现象仍未被现有综述和统一评测覆盖？

不变。极端少样本（1-2 shot）下的 PEFT 行为和跨方法方差结构仍未被系统研究。

### 5. 工程图/SysML 副线是必要的研究验证场，还是仅为比赛包装？

**修订**：新方案（文本生成+错误注入）使其成为**真正的验证场**——标签少、分布特殊、错误代价高、客观正确性标准。不再是比赛包装。

### 6. 如果删除所有界面和 Agent 话术，剩下的科学问题是否仍然成立？

**强化**：第一篇不涉及任何 Agent 话术或界面。科学问题是纯统计的。

### 7. 哪个最小实验能在 1-2 天内否定最推荐选题？

不变。3 方法 × 3 数据集 × 5 种子。（如果跨种子排名稳定性 >0.95 且选择后悔值趋近于零。）

## 不确定项（需确认）

1. ⚠️ **AutoPEFT 已报告的可靠性措施**（你已确认：5 种子均值±标准差、低保真与完整训练排名一致性）。需要确认这些报告的具体范围：是否覆盖小验证集？是否量化了选择后悔值？如果没有，写清我们的差异化。

2. ⚠️ **EHPO（NeurIPS 2021）框架**：已确认其一般性结论（"只有重复搜索确认后 HPO 结论才可信"）。我们的差异化必须在论文引言中明确声明：不做一般性理论贡献，而是在小数据视觉 PEFT 场景中提供 EHPO 原则的系统实证实例化和预算分配规律。

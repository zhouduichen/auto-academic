## 选题 1 🥇：ReliablePEFT——小数据视觉 PEFT 自动选择的稳定性与选择偏差基准

> ⚠️ 修订于 2026-07-30：原"预算感知 PEFT Agent"方案因 AutoPEFT/BIPEFT/MetaPEFT/DataMaster 等密集相邻工作而重新定义。

### 研究问题

**不是**"能不能自动找到最优 PEFT 配置"（AutoPEFT/BIPEFT 已解决），而是：

1. 不同随机种子、数据划分和验证集规模下，PEFT 方法排名是否稳定？
2. 搜索配置越多，验证集最优值与真实测试性能之间的选择后悔值是否越大？
3. 使用风险规避策略（选"较好且稳定"的配置而非"验证准确率最高"的配置），能否降低选择后悔值？

### 研究假设

H1：PEFT 方法排名在跨种子/跨划分时发生逆转（Kendall's W < 0.8），逆转频率随验证集减小而增加。
H2：搜索配置数增加时，Naive Max（选验证准确率最高）的选择后悔值单调增加——验证集过拟合。
H3：LCB / Bootstrap 下分位数 / Pareto 过滤的选择后悔值显著低于 Naive Max（p<0.05, Wilcoxon）。

### 方法：三种风险规避策略

1. **Lower Confidence Bound (LCB)**：`score = mean_val_acc − λ × std_val_acc`
2. **Bootstrap 下分位数**：N 次 bootstrap 重采样验证集，取第 5 百分位
3. **Pareto 前沿过滤**：排除被支配配置，在 Pareto 前沿中取最保守配置

### 基线

- **Naive Max**（AutoPEFT/BIPEFT 的做法）：选验证准确率最高的配置
- **Oracle**（上界）：选真实测试准确率最高的配置
- **Random**（下界）：随机选配置

### 数据集

- VTAB-1K（19 任务）
- FGVC（5 数据集）
- + 人工标签噪声注入（0%/5%/10%/20%）

### 评价指标

- **选择后悔值**（核心）：TestAcc(oracle) − TestAcc(selected)
- 排名稳定性（Kendall's W）
- 最差情况性能
- 5 种子 × 3 验证集规模（10%/20%/50%）的均值 ± 95% CI

### 最小否证实验

6 方法 × 3 数据集 × 5 种子 = 可自动运行的批量实验。三个否证条件：全部排名稳定 + 无搜索-过拟合 + Naive Max 后悔值趋零。

### 风险与缓解

| 风险 | 概率 | 缓解 |
|---|---|---|
| 简单方法无显著改善 | 低 | 负面结果仍有价值——量化了问题但解决不了 |
| 相邻工作抢先 | 中 | 聚焦跨种子/跨划分方差——已知空白 |
| 被审稿人认为"只是加了方差" | 低 | 系统量化选择后悔值 × 搜索次数的 trade-off 未被做过 |

### 评分表（修订）

| 维度 | 评分 | 理由 |
|---|---|---|
| 研究缺口强度 | 5 | 零篇 PEFT 论文系统量化选择可靠性——与"自动搜索"正交 |
| 单卡可行性 | 5 | 全部实验仅需运行已有方法 |
| 数据可得性 | 5 | 全公开 |
| 评测可信度 | 5 | 核心贡献就是可信评测 |
| 发表潜力 | 4 | CCF-C 起步，扎实后可冲 CCF-B；**负面结果也有价值** |
| 竞赛转化性 | 3 | 基准→工具 |
| 导师支持度 | 3 | 系统工程中验证思维 |
| 差异化 | 5 | **AutoPEFT/BIPEFT/MetaPEFT 全部选验证准确率最高——我们不选** |
| 一年延展性 | 5 | → 预算感知控制器（第二篇）→ 多模态 |
| **总分** | **40/45** | ⬆️ 原为 39（差异化的 5 vs 4 贡献了提升） | |

## 选题 2 🥈：视觉 PEFT 方法的稳定性与方差系统基准

### 研究问题
主流视觉 PEFT 方法（LoRA/SSF/VPT/Adapter/Convpass/BitFit）在跨种子、跨数据划分、跨域偏移下的排名稳定性和性能方差是多少？哪些方法-数据集组合对随机性最敏感？

### 研究假设
H1：不同 PEFT 方法在相同条件下可能产生不同的"最优方法"排名（逆转种子）。
H2：低参数方法（SSF/BitFit）在方差上优于高参数方法（LoRA/Adapter）。
H3：当前文献中基于单次运行的结论存在系统性偏差。

### 基线方法
- 6 种 PEFT 方法（LoRA/DoRA/SSF/VPT/Adapter/Convpass/BitFit）
- 全量微调上界 + CLIP 零样本下界

### 数据集
- VTAB-1K（19 任务）
- FGVC（5 数据集）
- ImageNet 变体（ImageNetV2/Sketch/A/R — 域偏移）

### 评价指标
- 跨种子排名稳定性（Kendall's W）
- 性能方差系数（CV = σ/μ）
- 最差情况性能（min across seeds）vs 均值性能
- 域偏移鲁棒性（源域→目标域退化率）
- 统计显著性矩阵（所有方法对的 McNemar + Bonferroni）

### 最小可行实验（1-2 天否证）
3 方法（LoRA/SSF/VPT）× 3 数据集（CIFAR-100/Caltech101/DTD）× 5 种子。
如果所有方法对所有数据集的跨种子排名保持稳定（Kendall's W > 0.9），则该选题的"稳定性危机"叙事被弱化（但其他维度仍可发表）。

### 风险与缓解
| 风险 | 概率 | 缓解 |
|---|---|---|
| 稳定性危机不够严重 | 低 | Pecher et al. 已在 415 篇论文中确认 |
| 被视为"纯工程" | 中 | 强调方法论贡献 + 统计建议 |
| PEFT-Bench 扩展（别人抢先） | 中 | 聚焦视觉（PEFT-Bench 仅 NLP）可差异化 |

### 评分表

| 维度 | 评分 | 证据/理由 |
|---|---|---|
| 研究缺口强度 | 5 | Pecher et al. 确认危机但无人执行视觉 PEFT 方差分析 |
| 单卡可行性 | 5 | 仅运行已有方法，无新训练需求 |
| 数据可得性 | 5 | 全公开数据集 |
| 评测可信度 | 5 | 本选题的核心贡献就是建立可信评测 |
| 发表潜力 | 4 | TMLR/NeurIPS D&B 适配 |
| 竞赛转化性 | 2 | 基准 ≠ 产品，但 IEEE 标准潜力 |
| 导师支持度 | 3 | 系统工程中的验证思维可借用 |
| 差异化 | 4 | 区别于 PEFT-Bench（NLP）和 CVPR 2025（无方差） |
| 一年延展性 | 4 | → 更多方法 → 更多模态 → 统计方法学 |
| **总分** | **37/45** | |

## 选题 3 🥉：公平比较 — LLM Agent vs 传统 AutoML 在预算约束微调下

### 研究问题
在相同 GPU 时间预算下（无云 API 依赖），LLM 引导的超参搜索是否显著优于 BOHB + 合理默认值？Agent 的推理能力在搜索效率方面提供多少增量？

### 研究假设
H1：在极小预算（<10 次试验）下，LLM Agent 的"常识先验"优于 BOHB 的冷启动。
H2：随着预算增加，BOHB 的采样效率将超越 Agent。
H3：Agent 的主要价值来自试验次数（多次尝试），而非推理质量本身。

### 基线方法
- **传统 AutoML**：BOHB, Hyperband, SMAC3, 随机搜索 + 合理默认值
- **LLM Agent**：AIDE 风格（GPT-4o 本地/开源模型），ML-Master 简化版
- **消融**：随机替换 LLM 推理（保留相同框架）

### 数据集
- VTAB-1K（视觉）
- HPOBench / YAHPO Gym 替代基准（快速评估）

### 评价指标
- GPU 时间归一化 regret
- 搜索效率（达到目标性能所需 GPU 时间）
- 有效试验率（不崩溃/不发散/不OOM的试验数/总试验数）
- Agent API 成本 vs 本地计算成本

### 最小可行实验（1-2 天否证）
BOHB vs 简化 Agent × VTAB-1K Natural × 3 预算水平。
如果 Agent 在所有预算下均未显著优于 BOHB（p<0.05），转向"Agent 何时有用"的诊断性贡献。

### 风险与缓解
| 风险 | 概率 | 缓解 |
|---|---|---|
| Agent 在所有条件下均不如 BOHB | 高 | 负面结果仍有发表价值（ICBINB/TMLR） |
| 开源 LLM 推理质量不足 | 中 | 使用 GPT-4o-mini 或 Claude Haiku（低成本 API） |
| 比较公平性争议 | 中 | 预设注册比较协议（类似 AMLB） |

### 评分表

| 维度 | 评分 | 证据/理由 |
|---|---|---|
| 研究缺口强度 | 5 | 零篇论文做此比较 |
| 单卡可行性 | 4 | 本地 BO 可行；开源 LLM 推理需额外 4-6GB |
| 数据可得性 | 5 | 全公开 |
| 评测可信度 | 5 | 核心贡献就是公平比较方法 |
| 发表潜力 | 3 | 负面结果可能性大；TMLR/ICBINB 路径窄 |
| 竞赛转化性 | 3 | 方法学贡献 |
| 导师支持度 | 3 | 间接相关 |
| 差异化 | 5 | 极强差异化——填补两个社区的鸿沟 |
| 一年延展性 | 4 | → 多保真度 Agent → 自改进 Agent |
| **总分** | **37/45** | |

## 选题 4：SysML v2 图示数据集与 VLM 理解基准

### 研究问题
SysML v2 图示（8 类型）的 VLM 理解能力基线是什么？能否创建首个公开 SysML v2 图示数据集并建立结构化理解基准？

### 研究假设
H1：VLM 在 SysML v2 图示上的结构化理解性能显著低于自然图像/UML。
H2：不同 VLM 在不同图示类型上表现差异显著。
H3：合成数据可生成可控错误用于诊断性评估。

### 基线方法
- GPT-4V/GPT-5.2, Claude 3.5 Sonnet, Gemini 2.0, 开源 VLM（LLaVA/Qwen-VL）
- 微调 Florence-2 / InternVL

### 数据集
- 新建：1,000-2,000 张 SysML v2 图示（8 类型 × 125-250 张）
- 来源：SysML v2 Pilot Implementation 示例 + 公开论文 + 合成生成

### 评价指标
- 分类准确率（图示类型识别）
- 结构化提取 F1（节点/边/属性）
- 语义一致性评分（人工 + CLIP-score）

### 最小可行实验（1-2 天否证）
收集 50 张 BDD + 50 张 IBD，GPT-4V 零样本分类 + 基本节点计数。
如果 GPT-4V 在分类上达到 >95% 准确率（说明太简单），则需提升难度（结构化提取代替分类）。

### 风险与缓解
| 风险 | 概率 | 缓解 |
|---|---|---|
| 数据收集耗时 | 高 | 优先使用公开示例 + Mermaid/PlantUML 生成 |
| SysML v2 太垂直 | 中 | 同时包含 UML（扩大受众） |
| VLM 能力快速提升导致基线过时 | 中 | 强调数据集和方法论，而非具体数值 |

### 评分表

| 维度 | 评分 | 证据/理由 |
|---|---|---|
| 研究缺口强度 | 5 | 零个公开 SysML v2 数据集 |
| 单卡可行性 | 4 | VLM 推理可用 API；微调可用 16GB |
| 数据可得性 | 3 | 需创建，但有公开来源 |
| 评测可信度 | 4 | 结构化标注 = 客观指标 |
| 发表潜力 | 4 | NeurIPS D&B / LREC |
| 竞赛转化性 | 5 | IEEE SysML 竞赛天然场景 |
| 导师支持度 | 5 | 直接挂钩系统工程/MBSE |
| 差异化 | 4 | 首个 SysML v2 + VLM 数据集 |
| 一年延展性 | 3 | 数据集扩展，但方法线较窄 |
| **总分** | **37/45** | |

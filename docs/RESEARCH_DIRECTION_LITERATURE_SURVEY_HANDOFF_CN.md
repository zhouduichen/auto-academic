# 研究方向文献调研任务书

> 用途：交给后续 AI Agent 执行系统性文献调研。  
> 状态：只做文献检索、分类、对比与选题建议；本阶段不编写训练代码，不启动 GPU 实验，不预设最终论文题目。  
> 编制日期：2026-07-29

## 1. 背景与目标

项目已搭建 Mac 控制端、Windows GPU 执行端以及自动实验基础能力。可用主要算力为单张 RTX 5080 Laptop GPU（16 GB 显存）。用户对小数据量训练和参数高效微调感兴趣，愿意学习自动实验 Agent。实验室导师背景为系统工程/MBSE，但选题不必限定于系统工程。

研究方向已初步确定为：

- **主线**：面向小数据任务的预算感知自动微调 Agent。
- **副线**：工程图、系统架构图或 SysML 模型的理解、结构化与一致性校验。
- **成果目标**：可投 CCF B/C 类国际会议/期刊，或认可目录中的 T2/T3 期刊；同时能抽取为中国大学生创新创业、数字服务或建模类比赛项目。

本次调研的核心目的不是为既定方案寻找引用，而是先广泛阅读，用证据判断：

1. 哪些问题已经过度拥挤；
2. 哪些空白能在单张 16 GB GPU 上严谨验证；
3. 哪些贡献可以同时支撑论文和可演示系统；
4. 最终应优先做方法、评测基准、诊断性研究，还是工程系统。

## 2. 需要调研的五个文献簇

### A. 小数据视觉/多模态参数高效微调

检索 few-shot/low-shot learning、PEFT、LoRA/Adapter/Prompt Tuning、CLIP/VLM adaptation、data-efficient transfer learning、test-time adaptation、active learning 与样本选择。重点关注：

- 极少标注下的均值性能、方差、最差性能和校准；
- 对数据划分、随机种子、类不平衡和域偏移的敏感性；
- 参数量、显存、训练时间与准确率的 Pareto 关系；
- 哪些“新模块＋新损失＋涨点”方向已经高度同质化。

### B. 预算感知 AutoML 与自动微调

检索 multi-fidelity HPO、Bayesian optimization、Hyperband/ASHA、population-based training、early stopping、learning-curve extrapolation、budgeted AutoML、green AI 和 resource-aware adaptation。重点关注：

- 在固定 GPU 时间、标注预算或实验次数下优化最终模型；
- 数据子集、数据增强、PEFT 结构、超参数和训练资源的联合决策；
- 小预算下的搜索方法是否真正优于随机搜索和强手工基线；
- 搜索成本是否会抵消 PEFT 本身节约的成本。

### C. AI 自动实验/科研 Agent

检索 autonomous research agent、LLM for AutoML、automated machine learning engineer、experiment planning agent、self-improving research agent、code-generating research agent 及其基准。重点关注：

- Agent 的价值究竟来自推理，还是工具编排和试错次数；
- 如何与随机搜索、贝叶斯优化、进化算法等非 LLM 方法公平对比；
- 可复现性、无效实验率、代码失败率、计算成本和最终性能；
- 避免把“自动调用训练脚本”误写成科学贡献。

### D. 工程图、系统架构图与 SysML 理解

检索 diagram understanding、chart/flowchart parsing、engineering drawing understanding、model-to-text/text-to-model、SysML/SysML v2 generation、MBSE with LLM/VLM、model validation、constraint checking 和 graph reconstruction。重点关注：

- 图像到结构化图/模型的节点、边、属性和约束恢复；
- 语法合法不等于语义正确，应如何评测语义一致性；
- 现有公开数据集、开源解析器、SysML v2 规范和可执行校验器；
- 是否可用合成数据生成可控错误，并保持评测有效性。

### E. 评测基准、数据集和诊断性研究

不要默认贡献必须是一个新模型。调查以下可能性：

- 小数据 PEFT 的稳定性/效率评测基准；
- 自动微调 Agent 在固定预算下的公平比较协议；
- 系统架构图的结构化理解与语义错误注入数据集；
- 负面结果、失败模式和统计显著性能否构成有价值的诊断性论文。

## 3. 检索与阅读规范

### 3.1 时间范围

- 广泛检索以 2022—2026 年为主，必须覆盖最新已公开论文。
- 对奠基方法可向前追溯，不得为追求“新”而忽略经典强基线。
- 对 2026 年尚未正式出版的工作，明确标注 preprint/录用/已出版状态。

### 3.2 广度与深度

- 第一层：通过标题、摘要和图表快速筛查不少于 **60 篇**候选工作。
- 第二层：精读不少于 **24 篇**，五个文献簇都需覆盖。
- 第三层：选出 **8—12 篇**直接决定选题的核心论文，追踪其代码、数据、实验设置、引用链和后续工作。

数量是最低要求，不是把不相关论文凑入表格的目标。

### 3.3 来源与引用完整性

- 优先使用出版社/会议官方页、OpenReview、ACL Anthology、IEEE/ACM 数字图书馆、CVF Open Access、作者仓库和 arXiv。
- 每篇记录：标题、作者、年份、会议/期刊、官方链接/DOI、代码、数据、算力、主要结论和局限。
- 不得仅根据搜索摘要生成结论；核心论文必须阅读正文的方法、实验和局限部分。
- 不得臆测 CCF/T 等级。投稿建议必须按调研当日的 CCF 官方目录和用户所属学院认定文件逐项核对。

## 4. 硬性约束与排除标准

候选方向原则上应当：

- 能在单张 16 GB NVIDIA GPU 上完成主要实验，允许极少量云算力作最终复验，但不得以多卡集群为成立前提；
- 优先使用可公开获得或可合法合成的数据，不依赖电机、轴承、齿轮箱、泵、风机、机床等物理试验台；
- 有至少三个公开数据集或足够严谨的跨域评测方案；
- 有可量化的强基线、可统计重复的评价指标与明确失败条件；
- 能从同一研究核心产生比赛演示，但不以“做了一个界面”代替论文贡献。

优先排除：

- 只更换 LoRA 插入位置、只叠加注意力模块、只设计新损失且缺少机理证据的微小涨点工作；
- 只在一个小数据集上比较，或只报告单一随机种子最优值的工作；
- 依赖专有大模型、不可导出实验记录或无法重复评估的 Agent 方案；
- 需要难以获得的企业私有数据、专用设备或高额标注成本的方向；
- 评价主要依赖主观案例展示，无法形成可审稿量化证据的方向。

## 5. 文献记录表字段

每篇进入候选库的论文至少记录：

| 字段 | 内容 |
|---|---|
| 基本信息 | 标题、年份、会议/期刊、链接、出版状态 |
| 问题 | 论文真正解决的可检验问题 |
| 贡献类型 | 方法/数据/基准/系统/诊断研究 |
| 方法 | 足以与其他工作区分的核心机制 |
| 实验 | 数据集、基线、指标、随机种子/置信区间 |
| 算力 | GPU 类型/数量、训练时间；未报告时明确标记 |
| 复现性 | 代码、配置、数据和模型权重是否可用 |
| 最强证据 | 最能支持论文主张的结果 |
| 局限/失败 | 作者承认的局限和调研者发现的缺口 |
| 与本项目关系 | 可复用基线、冲突点、可延伸空白 |
| 目录等级 | 当日官方目录与核验链接；不确定时留空 |

## 6. 候选方向评分标准

文献综述完成后，提出 3—5 个候选研究问题。每项按 1—5 分评估，并给出证据：

| 维度 | 判定要点 |
|---|---|
| 研究缺口强度 | 是真实未解决问题，还是换名包装 |
| 单卡可行性 | 16 GB 显存和合理 GPU 时间内能否做完 |
| 数据可得性 | 数据是否公开、合法、足够多样 |
| 评测可信度 | 是否有强基线、重复实验和客观指标 |
| 发表潜力 | CCF B/C 或 T2/T3 适配性，不许诺录用 |
| 竞赛转化性 | 能否转换成真实用户故事和可演示产品 |
| 导师支持度 | 是否能利用系统工程/MBSE 知识 |
| 差异化 | 与普通 PEFT 涨点或通用 Agent 的距离 |
| 一年延展性 | 是否能从首篇稳妥工作延伸到更高目标 |

## 7. 必须交付的文件

将调研结果放入 `docs/research-direction/`，交付：

1. `01_landscape.md`：五个文献簇的研究地图、发展时间线和关键派别。
2. `02_paper_matrix.csv`：不少于 60 篇候选论文的结构化表格。
3. `03_deep_reading_notes.md`：不少于 24 篇精读笔记，其中 8—12 篇标记为核心。
4. `04_gap_analysis.md`：已被充分解决的问题、仍然可信的空白以及每项空白的文献证据。
5. `05_candidate_topics.md`：3—5 个可执行选题，包含研究问题、假设、基线、数据、指标、最小实验、风险和评分表。
6. `06_venue_fit.md`：候选 CCF B/C 与 T2/T3 投稿去向、范围匹配、官方等级链接和风险；分清会议与期刊。
7. `07_recommendation.md`：最终建议的一条主线和一条备选线，同时写明为什么放弃其他方向。

所有 Markdown 结论必须就近附上可点击来源。CSV 中一篇论文一行，不得把同一工作的 arXiv 版和出版版重复计数。

## 8. 最终决策必须回答的问题

1. “自动微调 Agent”相比标准 AutoML/HPO 的可证伪新意是什么？
2. 在不增加总预算的前提下，Agent 应优化什么：均值性能、最差性能、稳定性、校准，还是 Pareto 前沿？
3. 最强非 Agent 基线是什么，为什么预期能超过它？
4. 小数据微调的哪个现象仍未被现有 PEFT 综述和统一评测覆盖？
5. 工程图/SysML 副线是必要的研究验证场，还是仅为比赛包装？
6. 如果删除所有界面和 Agent 话术，剩下的科学问题是否仍然成立？
7. 哪个最小实验能在 1—2 天内否定最推荐选题？

## 9. 执行边界

- 本阶段只读、只分析、只写调研交付物。
- 不修改现有训练系统，不安装大型依赖，不下载大模型/大数据集，不启动长时间 GPU 任务。
- 可以为核实论文元数据或官方分类浏览互联网，并必须保留来源链接。
- 发现候选题目后不立即实现；先提交调研结果，由用户确认主题。
- 如果学院对作者顺序、第一署名单位或与高年资合作有特殊计分规则，只记录风险，不自行解读为确定结论。
